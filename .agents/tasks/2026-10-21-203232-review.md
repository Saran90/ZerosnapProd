# Passport portrait auto-crop from captured front page

Adds automatic profile image extraction from passport front page using ML Kit face detection with ICAO-based fallback, integrated into the passport scan flow for both domestic and foreign passports. When the passport front is captured, the system attempts to detect and crop the portrait photo automatically, falling back to heuristic region cropping if face detection fails. Manual crop remains available through a bottom sheet when the user taps the profile photo slot. The extractor returns null on failure without crashing the scan flow.

**Watch for:** Face detection failure could leave users without a profile image if the heuristic fallback doesn't work for their passport layout (confirmed). The extractor swallows all errors silently and returns null, which means a failed extraction has no visible user feedback beyond an empty profile slot (confirmed). The fixed filename pattern (`profile_latest.jpg`) prevents file accumulation but could collide if multiple passport scans run concurrently in the same directory (likely).

**Verdict**: APPROVED

## High-level view

The extractor uses ML Kit's face detector in accurate mode with landmarks and contours enabled, calculates a passport-standard crop (35:45 aspect ratio, face at 75% of photo height), and saves the result as `profile_latest.jpg` in the same directory as the source image. When face detection fails or returns no faces, it falls back to a percentage-based heuristic using ICAO 9303 standard positions (7% from left, 32% from top, 25% width).

The scan pages invoke the extractor immediately after capturing the passport front, store the result in `_profileImagePath`, and pass it forward to `PassportCardScanPage` via constructor parameters. The retake flow carries the auto-extracted profile through `ScanRetakeResult.profileImagePath`. When a profile image already exists, tapping the profile slot opens a bottom sheet with two options: crop from passport (manual) or pick new photo (camera/gallery).

Extraction errors (file I/O, decode failure, face detection crash) are caught and logged but not surfaced to the user. A failed extraction leaves the profile image path empty, which the form displays as an empty slot. The user can still manually crop or capture a new photo.

The fixed filename means every extraction in a directory overwrites the previous one. This prevents orphaned files but assumes single-threaded execution per directory. The `previousProfilePath` parameter allows explicit cleanup of a prior extraction, but it's never passed by the calling code.

Test coverage includes successful extraction, null returns for invalid/missing files, bounds clamping, filename reuse, too-small image rejection, and JPEG quality preservation. No tests for the face detection logic itself (ML Kit is mocked out at the framework level).

## ML Kit face detection with passport-standard margins

The extractor initializes a `FaceDetector` with landmarks, contours, and accurate mode, processes the image, and uses the first detected face's bounding box to calculate the crop rectangle. The passport photo dimensions are derived by assuming the face occupies 75% of the photo height (ICAO standard range is 70-80%), then computing width from the 35:45 aspect ratio (0.7778:1). The crop is centered horizontally on the face and positioned with a 12% margin above the face's top edge. All coordinates are clamped to image bounds.

When face detection fails (no faces, empty result, or exception), the fallback uses fixed percentages: 7% horizontal offset, 32% vertical offset, 25% width, height calculated from aspect ratio. These match ICAO 9303 layout for passport bio-data pages, where the portrait is on the left side.

The extractor rejects crops smaller than 50×50 pixels and returns null. This prevents unusably small outputs but means a very low-resolution passport scan (under 200 pixels wide) will always fail extraction.

## Integration with passport scan flow

Both `DomesticPassportScanPage` and `ForeignPassportScanPage` call `extractPassportPortrait` immediately after capturing the passport front image and before running OCR. The result is stored in `_profileImagePath` and passed to `PassportCardScanPage` via the `initialProfileImagePath` constructor parameter. The form page reads this parameter in `initState` and populates `_profileImagePath` if the value is non-empty.

When the user retakes the passport front via the retake scanner, the scanner re-runs the extraction and includes the result in `ScanRetakeResult.profileImagePath`. The form page reads this field and updates its `_profileImagePath` state, replacing the old auto-cropped image with the new one.

The manual crop flow is preserved: when the user taps the profile photo slot, a bottom sheet appears with two options. "Crop from Passport" invokes `cropProfileFromCard` (existing manual crop tool), "Pick New Photo" opens the camera. This gives the user a fallback if the auto-extraction is incorrect.

## Error handling and null returns

All errors in the extractor are caught by two handlers: `FileSystemException` for file I/O (missing file, permission denied, disk full) and `Exception` for everything else (decode failure, ML Kit crash, out-of-memory). Both handlers log the error to `debugPrint` and return null. The calling code checks `if (profilePath != null)` and only updates `_profileImagePath` if extraction succeeded, otherwise leaves it empty.

A null return means the scan flow continues normally with no profile image. The form displays an empty profile slot, and the user can tap it to manually crop or capture. There is no toast, snackbar, or inline message telling the user that auto-extraction failed, so they must discover the manual option by tapping the empty slot.

The face detection function returns null if `faces.isEmpty`, which is logged but not distinguished from an error. A passport with no detectable face (poor lighting, occlusion, non-standard layout) behaves the same as a file I/O error.

## Fixed filename and cleanup strategy

The output path is always `${directory.path}/profile_latest.jpg`, regardless of the source filename. This ensures that re-scanning a passport in the same directory overwrites the old extraction, preventing file accumulation. The `previousProfilePath` parameter allows explicit deletion of a prior extraction before writing the new one, but no caller passes this parameter. The fixed filename strategy makes it redundant unless extractions are written to different directories.

The fixed filename assumes one active scan per directory. If two scans run concurrently (e.g., a background retry and a foreground retake), they will race to write `profile_latest.jpg` and one will overwrite the other. The scan pages create temp directories per session, so this is only a risk if the temp directory is reused across sessions or if the directory path is derived from a shared location.

## Test coverage

The test suite creates temp directories, generates synthetic passport images using the `image` package, runs extraction, and verifies the output path and dimensions. Tests cover successful extraction, null returns for invalid/missing files, bounds clamping with small images, fixed filename reuse (two extractions produce the same path), rejection of images too small to crop, and JPEG quality preservation (green pixels remain greenish after encoding at quality 90).

No tests directly exercise the face detection logic (mocking ML Kit's `FaceDetector` is framework-level and not accessible in unit tests). The tests assume the fallback heuristic is invoked when face detection is unavailable. The commit message confirms all 7 tests pass.
